# 第6章：推論設定の完全解説

## 6.1 推論パラメータの基礎

### 6.1.1 推論プロセスの理解

LLMの推論（テキスト生成）は、確率的なプロセスです。

**基本的な流れ:**

```
1. プロンプト入力
   ↓
2. トークン化（文章をトークンに分割）
   ↓
3. エンコード（コンテキスト理解）
   ↓
4. デコード（次のトークンを予測）
   ↓
5. サンプリング（確率分布から選択）
   ↓
6. トークン生成
   ↓
7. 4に戻る（終了条件まで繰り返し）
```

**サンプリング**が、推論設定の核心です。モデルは各ステップで「次に来るトークンの確率分布」を出力します。

```
例: "私は" の次のトークン確率分布

"学生": 25%
"教師": 18%
"医者": 12%
"エンジニア": 10%
...その他...
```

推論パラメータは、この確率分布からどのようにトークンを選択するかを制御します。

### 6.1.2 決定論的 vs 確率的生成

**決定論的生成（Temperature = 0）**
```
特徴: 常に最も確率の高いトークンを選択
結果: 同じプロンプトで常に同じ出力
用途: 事実確認、コード生成、一貫性が重要な場合
```

**確率的生成（Temperature > 0）**
```
特徴: 確率に基づいてランダムにトークンを選択
結果: 同じプロンプトで異なる出力
用途: 創造的な文章、ブレインストーミング、多様な応答
```

## 6.2 主要パラメータの詳細解説

### 6.2.1 Temperature（温度）

**定義:** 確率分布の「鋭さ」を制御するパラメータ

#### 設定範囲と効果

```
設定範囲: 0.0 〜 2.0
デフォルト: 0.7
推奨範囲: 0.3 〜 1.0
```

**数値と効果の関係:**

**Temperature = 0.0（決定論的）**
```
確率分布:
  "学生": 100% ←必ず選択
  "教師": 0%
  "医者": 0%

特徴:
  ✓ 完全に予測可能
  ✓ 一貫性が高い
  ✓ 創造性ゼロ

用途:
  - 数学問題の解答
  - コード生成
  - 事実の列挙
  - 翻訳（正確性重視）
```

**Temperature = 0.3（低温・保守的）**
```
確率分布:
  "学生": 60%
  "教師": 30%
  "医者": 8%
  その他: 2%

特徴:
  ✓ 予測可能性が高い
  ✓ 安全な選択
  ✓ 軽微なバリエーション

用途:
  - ビジネス文書
  - 技術文書
  - FAQの応答
  - カスタマーサポート
```

**Temperature = 0.7（標準・バランス）**
```
確率分布:
  "学生": 32%
  "教師": 24%
  "医者": 16%
  "エンジニア": 13%
  その他: 15%

特徴:
  ✓ バランスが良い
  ✓ 適度な創造性
  ✓ 自然な会話

用途:
  - 日常会話
  - ブログ記事
  - メール返信
  - 汎用チャット ← 最も推奨
```

**Temperature = 1.0（高温・創造的）**
```
確率分布:
  "学生": 25%
  "教師": 20%
  "医者": 15%
  "エンジニア": 12%
  "芸術家": 10%
  その他: 18%

特徴:
  ✓ 創造的
  ✓ 多様な表現
  ✓ 予測困難

用途:
  - 小説・物語の執筆
  - ブレインストーミング
  - 詩の生成
  - アイデア出し
```

**Temperature = 1.5-2.0（非常に高温・実験的）**
```
確率分布: ほぼ均一

特徴:
  ⚠️ 非常にランダム
  ⚠️ 一貫性の欠如
  ⚠️ ナンセンスな出力の可能性

用途:
  - 実験的な創作
  - ランダム性が必要な場合
  注意: 通常使用は非推奨
```

**💡 TIP**: MS-S1 Maxでは、Temperature 0.7がほとんどの用途で最適です。

### 6.2.2 Top P（Nucleus Sampling）

**定義:** 累積確率がPに達するまでのトークン集合から選択

#### 設定範囲と効果

```
設定範囲: 0.0 〜 1.0
デフォルト: 0.95
推奨範囲: 0.85 〜 1.0
```

**動作原理:**

```
確率分布（降順）:
  "学生": 25%  累積: 25%  ← Top P = 0.25ならここまで
  "教師": 18%  累積: 43%  ← Top P = 0.43ならここまで
  "医者": 12%  累積: 55%
  "エンジニア": 10%  累積: 65%
  "芸術家": 8%   累積: 73%
  "料理人": 6%   累積: 79%
  ...

Top P = 0.95の場合:
  累積95%に達するまでのトークンから選択
  → 約20-30個のトークンが候補
```

**数値と効果:**

**Top P = 0.5（非常に制限的）**
```
効果:
  - 上位50%の確率のトークンのみ考慮
  - 非常に保守的
  - 予測可能性が高い

推奨用途:
  - 事実に基づく回答
  - 専門的な内容
```

**Top P = 0.75（やや制限的）**
```
効果:
  - 上位75%のトークンから選択
  - バランスの取れた出力
  - 適度な多様性

推奨用途:
  - ビジネス文書
  - 技術文書
```

**Top P = 0.95（標準）**
```
効果:
  - 上位95%のトークンから選択
  - 自然な多様性
  - 低確率トークンも考慮

推奨用途:
  - 日常会話 ← 最も推奨
  - 創造的文章
```

**Top P = 1.0（無制限）**
```
効果:
  - すべてのトークンが候補
  - 最大の多様性
  - 稀なトークンも選択可能

推奨用途:
  - 実験的創作
  - 最大限の創造性
```

**💡 TIP**: Top P = 0.95がほとんどの場合で最適です。

### 6.2.3 Top K

**定義:** 確率上位K個のトークンのみから選択

#### 設定範囲と効果

```
設定範囲: 0 〜 100（通常）
デフォルト: 40
推奨範囲: 20 〜 60
特殊値: 0 = 無効（Top Kを使用しない）
```

**動作原理:**

```
確率分布:
  1. "学生": 25%
  2. "教師": 18%
  3. "医者": 12%
  4. "エンジニア": 10%
  5. "芸術家": 8%
  ... （続く）

Top K = 3の場合:
  → 上位3つ（学生、教師、医者）からのみ選択

Top K = 40の場合:
  → 上位40個のトークンから選択
```

**Top P vs Top K:**

```
Top P（Nucleus Sampling）:
  ✓ 動的な候補数（確率分布に依存）
  ✓ コンテキストに適応
  ✓ より自然な出力
  推奨: ✅

Top K:
  ✓ 固定の候補数
  ✓ 予測可能
  ✓ 実装がシンプル
  推奨: 補助的に使用
```

**推奨設定:**

```
標準設定:
  Top P = 0.95
  Top K = 40

保守的設定:
  Top P = 0.85
  Top K = 20

創造的設定:
  Top P = 1.0
  Top K = 60
```

### 6.2.4 Repeat Penalty（繰り返しペナルティ）

**定義:** 既に生成されたトークンの再出現にペナルティを課す

#### 設定範囲と効果

```
設定範囲: 1.0 〜 1.5
デフォルト: 1.1
推奨範囲: 1.05 〜 1.15
特殊値: 1.0 = ペナルティなし
```

**動作原理:**

```
生成済みテキスト: "私は学生です。私は..."

次のトークン予測（ペナルティ前）:
  "学生": 30%
  "教師": 20%
  "毎日": 15%

Repeat Penalty = 1.1 適用後:
  "学生": 30% / 1.1 = 27.3%  ← ペナルティ
  "私": 25% / 1.1 = 22.7%    ← ペナルティ
  "は": 22% / 1.1 = 20%       ← ペナルティ
  "教師": 20%（変化なし）
  "毎日": 15%（変化なし）

再正規化後、選択
```

**数値と効果:**

**Repeat Penalty = 1.0（ペナルティなし）**
```
効果: 繰り返しを防がない
結果:
  ⚠️ 同じフレーズの繰り返し
  ⚠️ 「そして、そして、そして...」
推奨用途: 通常使用しない
```

**Repeat Penalty = 1.05（軽微）**
```
効果: 軽いペナルティ
特徴:
  ✓ 自然な繰り返しは許容
  ✓ 過度な繰り返しを抑制
推奨用途:
  - 詩、歌詞（意図的な繰り返しがある）
  - 自然な会話
```

**Repeat Penalty = 1.1（標準）**
```
効果: 適度なペナルティ
特徴:
  ✓ バランスが良い
  ✓ 不自然な繰り返しを防ぐ
  ✓ 語彙の多様性を維持
推奨用途:
  - 日常会話 ← 最も推奨
  - 文章生成
  - ほとんどの用途
```

**Repeat Penalty = 1.15-1.2（強い）**
```
効果: 強いペナルティ
特徴:
  ✓ 繰り返しをほぼ防ぐ
  ⚠️ やや不自然になる可能性
推奨用途:
  - 長文生成
  - リスト作成（重複回避）
```

**Repeat Penalty = 1.3+（非常に強い）**
```
効果: 非常に強いペナルティ
結果:
  ⚠️ 不自然な語彙選択
  ⚠️ 文脈に合わない単語
推奨用途: 通常使用しない
```

### 6.2.5 Context Length（コンテキスト長）

**定義:** モデルが一度に処理できるトークン数

#### 設定とトレードオフ

```
設定範囲: 512 〜 モデルの最大値（8K, 32K, 128K等）
デフォルト: モデル依存（通常4K-8K）
推奨設定: 用途に応じて調整
```

**モデル別最大コンテキスト:**

| モデル | 最大コンテキスト | 推奨設定（MS-S1 Max） |
|--------|----------------|----------------------|
| Qwen2.5 7B | 32K (32768) | 16K-32K |
| Qwen2.5 14B | 32K | 16K-32K |
| Qwen2.5 32B | 32K | 16K-32K |
| Qwen2.5 72B | 128K (131072) | 32K-64K |
| Llama 3.1 8B | 128K | 32K-64K |
| Llama 3.1 70B | 128K | 16K-32K |

**コンテキスト長とメモリ使用量:**

```
基本計算式:
追加メモリ ≈ (コンテキスト長 / 1024) × (パラメータ数 / 1B) × 0.15 GB

例: Qwen2.5 7B、32Kコンテキスト
追加メモリ ≈ (32768 / 1024) × (7.62 / 1) × 0.15
          ≈ 32 × 7.62 × 0.15
          ≈ 36.6 GB

モデル本体: 4.8GB
コンテキスト: 36.6GB（32K設定時）
合計: 約41GB
```

**コンテキスト長の選択:**

**2K-4K（短い）**
```
用途:
  - 短い質問応答
  - シンプルなチャット
  - 高速応答が必要な場合

メモリ: 最小
速度: 最速
```

**8K-16K（中程度）**
```
用途:
  - 通常の会話
  - 中程度の文書処理
  - バランス型 ← 推奨

メモリ: 中程度
速度: 高速
```

**32K-64K（長い）**
```
用途:
  - 長文の要約
  - 複数の文書の比較
  - 長い会話履歴の保持

メモリ: 大きい
速度: 中速
```

**128K（非常に長い）**
```
用途:
  - 書籍全体の分析
  - 超長文の処理
  - 専門的な用途

メモリ: 非常に大きい
速度: やや遅い
制約: 128GBメモリでも70Bモデルでは困難
```

**💡 TIP**: MS-S1 Maxでは、16K-32Kが実用的なバランスポイントです。

### 6.2.6 Max Tokens（最大生成トークン数）

**定義:** 一度の応答で生成する最大トークン数

```
設定範囲: 1 〜 32768（コンテキスト長以下）
デフォルト: 2048
推奨範囲: 512 〜 4096
```

**用途別推奨値:**

```
短い応答（チャット）: 512-1024
中程度の応答（説明）: 1024-2048
長い応答（文章生成）: 2048-4096
非常に長い（記事執筆）: 4096-8192
```

**⚠️ 注意**: 大きな値を設定しても、モデルが終了条件（EOS）を生成すれば、そこで停止します。

### 6.2.7 その他の高度なパラメータ

#### Frequency Penalty（頻度ペナルティ）

```
設定範囲: 0.0 〜 2.0
デフォルト: 0.0
推奨: 0.0 〜 0.3

効果:
  - トークンが既に出現した回数に応じてペナルティ
  - Repeat Penaltyより細かい制御
  - 0.0 = ペナルティなし
```

#### Presence Penalty（存在ペナルティ）

```
設定範囲: 0.0 〜 2.0
デフォルト: 0.0
推奨: 0.0 〜 0.3

効果:
  - トークンが既に出現したかどうかにペナルティ
  - 新しいトピックへの移行を促進
  - 0.0 = ペナルティなし
```

#### Mirostat

```
設定: 0, 1, 2
デフォルト: 0（無効）

Mirostat 0: 無効
Mirostat 1: 動的パープレキシティ制御
Mirostat 2: 改良版

効果:
  - 出力の一貫性を動的に調整
  - Temperature、Top P、Top Kを上書き
  - 実験的機能

推奨: 通常は無効（0）
```

### 6.4.2 トラブルシューティング

#### 問題1: 繰り返しが多い

```
症状:
  "そして、そして、そして..."
  同じフレーズの連続

解決策:
  ✓ Repeat Penaltyを上げる: 1.1 → 1.15
  ✓ Frequency Penaltyを有効化: 0.2
  ✓ Temperatureを少し上げる: 0.7 → 0.8
```

#### 問題2: 一貫性がない・支離滅裂

```
症状:
  話題がコロコロ変わる
  文脈を無視した応答

解決策:
  ✓ Temperatureを下げる: 0.9 → 0.6
  ✓ Top Pを下げる: 0.98 → 0.92
  ✓ Top Kを下げる: 60 → 35
```

#### 問題3: 創造性がない・つまらない

```
症状:
  毎回似たような応答
  予測可能すぎる

解決策:
  ✓ Temperatureを上げる: 0.5 → 0.8
  ✓ Top Pを上げる: 0.85 → 0.95
  ✓ Repeat Penaltyを下げる: 1.15 → 1.05
```

#### 問題4: 途中で停止する

```
症状:
  文章が途中で終わる
  不完全な応答

解決策:
  ✓ Max Tokensを増やす: 1024 → 2048
  ✓ Context Lengthを確認（十分か？）
  ✓ モデルを再ロード
```

## 6.5 パフォーマンスとの関係

### 6.5.1 パラメータと速度

**速度に影響するパラメータ:**

```
Context Length: 大 ← 最も影響大
  8K → 16K: 速度 約15%低下、メモリ 約2倍
  16K → 32K: 速度 約15%低下、メモリ 約2倍

Max Tokens: 中程度の影響
  1024 → 4096: 生成時間 4倍（トークン数に比例）

Temperature, Top P, Top K: 小
  サンプリング計算のオーバーヘッドは軽微
```

**MS-S1 Max最適化設定:**

```
高速優先:
  Context: 8K
  Max Tokens: 1024
  推定速度: 35-45 t/s（7Bモデル）

バランス:
  Context: 16K
  Max Tokens: 2048
  推定速度: 30-40 t/s（7Bモデル）

品質優先:
  Context: 32K
  Max Tokens: 4096
  推定速度: 25-35 t/s（7Bモデル）
```

### 6.5.2 メモリとコンテキスト長の関係

**メモリ使用量計算表（Qwen2.5 7B Q4_K_M）:**

| Context Length | モデル | コンテキスト | 合計 |
|---------------|--------|-------------|------|
| 4K | 4.8GB | 9GB | 13.8GB |
| 8K | 4.8GB | 18GB | 22.8GB |
| 16K | 4.8GB | 36GB | 40.8GB |
| 32K | 4.8GB | 72GB | 76.8GB |

**💡 TIP**: MS-S1 Maxの128GBメモリでも、7Bモデルで32K使用すると約77GB消費します。他のアプリケーション用に余裕を残しましょう。

## 6.6 本章のまとめ

本章では、推論設定の詳細について学習しました。

✅ **主要パラメータ**

- Top P: 0.95（推奨）
- Top K: 40（推奨）
- Repeat Penalty: 1.1（標準）

✅ **用途別最適化**
- 技術文書: 低Temperature、短Context
- 創作: 高Temperature、長Context
- チャット: バランス型

✅ **トラブルシューティング**
- 繰り返し → Repeat Penalty増
- 支離滅裂 → Temperature減
- 創造性不足 → Temperature増
